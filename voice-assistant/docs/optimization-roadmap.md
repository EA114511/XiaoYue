# 小玥 AI 语音助手 — 后续优化迭代方案

> **版本**: v1.1.0 → v2.x 规划  
> **目标**: 在现有 `voice-assistant/` 基础上，按阶段补齐核心体验、智能能力与工程成熟度，打造可长期维护的产品级语音助手。  
> **关联文档**: [feature-roadmap.md](feature-roadmap.md)（各功能详细实现方案）

---

## 1. 项目现状与已具备能力

### 1.1 已实现（v1.1.0 当前状态）

| 模块 | 已完成能力 |
|------|-----------|
| **语音核心** | Whisper ASR、WebRTC VAD、AI 语音大模型 TTS、WebSocket 二进制音频传输 |
| **对话能力** | 多轮对话、流式 LLM 响应（`stream_delta/stream_end`）、NLU 意图识别 |
| **多智能体** | Coordinator + 5 个 Specialist Agent，支持动态配置 |
| **Provider 体系** | LLM / 语音 Provider 注册表，运行时热切换 |
| **技能扩展** | 8 个内置技能 + MCP Bridge 外部工具接入 |
| **工程优化** | ASR/TTS/LLM 缓存、熔断器、并发控制、API Token 鉴权、Fernet 加密 |
| **前端体验** | 「月夜 · 明珠」设计、玥珠光球四态动效、AudioQueue 顺序播放 |

### 1.2 关键短板

| 问题 | 影响 |
|------|------|
| 录音仍需长按/点击 | 语音助手不够「无手化」 |
| 说话结束需手动松手 | 交互不自然，影响连贯性 |
| AI 播报时无法打断 | 用户必须等播报完才能说话 |
| 无长期记忆 | 每次对话都是「陌生人」 |
| 无知识库 | 无法基于用户文档回答 |
| 无用户体系 | 配置、历史、记忆无法隔离 |
| 缺少监控与可观测性 | 线上问题难以定位 |

按 **「核心体验 → 智能增强 → 产品成熟 → 工程 polish」** 分四阶段推进，每阶段控制在 2-4 周。

|------|------|---------|---------|

## 3. 第一阶段：自然交互体验（v1.2.0）

### 3.1 目标
让语音交互从「按住说话」升级为「随时唤醒、自然对话、可打断」的体验。

### 3.2 任务清单

| 优先级 | 功能 | 说明 | 关键文件 |
|--------|------|------|---------|
| P0 | **前端 VAD + 自动断句** | 按住说话后，检测到 800ms 静音自动停止并发送 | `useVAD.js`, `useVoiceChat.js` |
| P0 | **语音打断（Barge-in）** | AI 播报时用户说话，立即停止 TTS 并进入聆听 | `useVoiceChat.js`, `VoiceAssistant.vue` |
| P1 | **唤醒词检测** | 说出「小玥小玥」自动激活录音 | `useWakeWord.js`, `VoiceAssistant.vue` |
| P1 | **打断后免唤醒** | 打断后的新一轮录音无需再次唤醒词 | `useVoiceChat.js` |

### 3.3 技术要点

- **VAD 选型**: 前端 Silero VAD（`onnxruntime-web`）或继续使用 WebRTC VAD 的 JS 版本；后端 VAD 仅作为校验。
- **打断检测**: TTS 播放期间保持麦克风低功耗监听，音量阈值 + VAD 双重判定，避免误触发。
- **唤醒词**: Porcupine 中文自定义唤醒词，注意 `.ppn` 文件授权与浏览器 WASM 兼容性。

### 3.4 验收标准

- [x] 说完话 800ms 内自动停止录音并发送
- [x] AI 播报时说话，TTS 立即停止并进入 listening 状态
- [x] 说出唤醒词后自动触发录音并播放提示音
- [x] 安静环境下不误触发打断 / 自动断句

> **状态**：✅ 已完成（v1.2.0）

## 4. 第二阶段：智能增强（v1.3.0）

### 4.1 目标
让助手「记得住、查得到、帮得上」，从玩具级升级为可用级个人助手。

### 4.2 任务清单

| 优先级 | 功能 | 说明 | 关键文件 |
|--------|------|------|---------|
| P0 | **流式 TTS 播放** | LLM 每输出一句立即触发 TTS，边说边播 | `websocket.py`, `ai_voice.py`, `useVoiceChat.js` |
| P0 | **长期记忆系统** | 跨会话记住用户偏好、习惯、身份 | `memory.py`, `database.py`, `dialog.py` |
| P1 | **知识库 / RAG** | 用户上传 PDF/Word/TXT，基于文档问答 | `rag.py`, `endpoints.py` |
| P1 | **闹钟与定时提醒** | 「5 分钟后叫我」「明天 8 点叫我起床」 | `scheduler.py`, `reminder.py`, `websocket.py` |
| P2 | **记忆主动提取** | 对话结束后由 LLM 自动总结值得记忆的信息 | `memory.py` |

### 4.3 技术要点

- **流式 TTS**: 复用现有 `_call_llm_stream`，增加 `SentenceBuffer` 按句子切分，每句触发 `_tts_stream_and_send`。
- **长期记忆**:
  - SQLite 增加 `memories` 表（user_id / category / key / value / importance / updated_at）
  - 对话前检索相关记忆注入 system prompt
  - 对话后调用 LLM 提取记忆并保存
- **RAG**:
  - 文档切片 → 向量化（`sentence-transformers`）→ ChromaDB / SQLite 向量
  - 问答时检索 top-k 片段注入上下文
- **提醒**:
  - APScheduler 定时任务
  - 触发时通过 WebSocket 推送 `reminder` 消息，前端播放提示音

### 4.4 验收标准

- [ ] LLM 输出完整句子后，TTS 立即开始播报，无需等全部生成完
- [ ] 用户说「我喜欢周杰伦」，下次「放首歌」能推荐周杰伦
- [ ] 上传 PDF 后能回答文档内容，并标注来源
- [ ] 设置提醒后准时收到语音/文字提醒

## 5. 第三阶段：产品成熟（v1.4.0）

### 5.1 目标
支持多用户、真实设备、情绪感知，让产品具备家庭 / 小型团队使用条件。

### 5.2 任务清单

| 优先级 | 功能 | 说明 | 关键文件 |
|--------|------|------|---------|
| P0 | **多用户认证系统** | JWT 注册/登录，用户数据隔离 | `auth.py`, `database.py`, `endpoints.py`, `websocket.py` |
| P1 | **真实 IoT 设备集成** | 对接 Home Assistant / 米家，替代模拟设备 | `integrations/home_assistant.py`, `device.py` |
| P1 | **情绪识别** | 基于语音特征推断情绪，调整回复风格 | `useEmotionDetection.js`, `dialog.py` |
| P2 | **语音合成情感控制** | TTS 根据内容情感调整语气 | `ai_voice.py` |
| P2 | **录音保存与回放** | 保存用户录音与 AI 回复，支持下载/回放 | `endpoints.py`, 前端新增回放 UI |

### 5.3 技术要点

- **多用户**:
  - `users` 表 + JWT Token
  - WebSocket 连接时通过 query param 传递 token
  - 对话历史、记忆、Provider 配置全部按 `user_id` 隔离
- **IoT**:
  - Home Assistant WebSocket API 优先（生态最广）
  - 配置 `home_assistant_url` + `token`，未配置时回退到模拟设备
- **情绪识别**:
  - 简单版：基于音量 / 语速 / 音高推断
  - 进阶版：集成轻量级音频情绪模型

### 5.4 验收标准

- [ ] 不同用户登录后看到各自的历史对话和记忆
- [ ] 能控制真实的 Home Assistant 设备并查询状态
- [ ] 用户语气开心/生气时，助手回复风格相应调整
- [ ] 可下载单轮对话的录音和 TTS 回复

## 6. 第四阶段：工程成熟与生态（v1.5.0）

### 6.1 目标
提升可观测性、可安装性、性能与扩展性，为开源或商业化做准备。

### 6.2 任务清单

| 优先级 | 功能 | 说明 | 关键文件 |
|--------|------|------|---------|
| P1 | **PWA / 移动端适配** | 可安装为桌面/手机应用，支持离线基础功能 | `manifest.json`, `sw.js`, `VoiceAssistant.vue` |
| P1 | **性能监控面板** | 可视化 ASR/TTS/LLM 延迟、错误率、缓存命中率 | 后端指标收集 + 前端 `/monitor` 路由 |
| P1 | **插件 / 技能市场雏形** |  skill 目录支持热加载外部 Python 脚本 | `skills/__init__.py` |
| P2 | **后端性能优化** | 模型预热、连接池调优、缓存策略优化 | `asr.py`, `ai_voice.py`, `optimization.py` |
| P2 | **前端性能优化** | 懒加载、Canvas 降级、减少重绘 | `OrbCanvas.vue`, `NightSky.vue` |
| P2 | **完善测试覆盖** | 单元测试 + 集成测试覆盖核心流程 | `tests/` |

### 6.3 技术要点

- **监控面板**:
  - 后端用 Prometheus 风格指标或内存指标
  - 前端用 Chart.js 展示实时 / 历史数据
- **PWA**:
  - `manifest.json` + Service Worker 缓存静态资源
  - 离线时保留基础 UI 和本地历史
- **插件市场雏形**:
  - 约定 skill 接口：`class CustomSkill(BaseSkill)`
  - 启动时扫描 `backend/skills/plugins/` 目录自动注册

### 6.4 验收标准

- [ ] Chrome/Edge 可将应用安装到桌面/手机主屏
- [ ] 监控面板可查看 ASR/TTS/LLM 平均延迟和缓存命中率
- [ ] 新增 skill 只需放入指定目录并重启后端即可生效
- [ ] 核心模块单元测试覆盖率 > 70%

## 7. 非功能优化（贯穿各阶段）

| 维度 | 优化项 | 建议 |
|------|--------|------|
| **安全** | 密钥管理 | 所有 API Key 必须经 Fernet 加密后落盘，禁止明文日志 |
| **安全** | 鉴权 | 写接口必须校验 `X-API-Token`，多用户阶段升级为 JWT |
| **安全** | 输入校验 | 所有 LLM / TTS 入参做长度与格式限制 |
| **性能** | 模型加载 | ASR Whisper 模型启动时预加载，减少首次请求延迟 |
| **性能** | 缓存策略 | LLM 语义缓存按用户 + 模型维度隔离，避免跨用户污染 |
| **稳定性** | 错误处理 | WebSocket 断线自动重连，TTS/ASR 失败优雅降级为文字 |
| **可观测性** | 日志 | 统一结构化日志，关键路径记录 trace_id |
| **可维护性** | 代码规范 | 后端按 PEP8 + type hints，前端按 ESLint/Prettier |

## 8. 实施建议

### 8.1 每个阶段的通用流程

1. **设计评审**: 输出接口文档与数据模型变更
2. **后端实现**: 数据层 → 服务层 → API / WebSocket
3. **前端实现**: Composable → Component → 样式适配
4. **联调测试**: 覆盖主流程与异常路径
5. **更新文档**: README / CHANGELOG / API 文档同步
6. **版本发布**: 打 tag，更新 docker-compose 镜像版本

### 8.2 推荐的起手顺序

如果资源有限，建议先做 **第一阶段 + 第二阶段的核心项**，因为：

- VAD 自动断句 + 语音打断 → 直接提升语音交互自然度
- 流式 TTS → 让 AI 回复「听」起来更快
- 长期记忆 → 让助手从工具变成「有记忆」的助手

这三项做完，产品体验会有质的提升。

## 9. 风险与依赖

| 风险 | 影响 | 应对 |
|------|------|------|
| Porcupine 中文唤醒词授权 | 唤醒词功能受限 | 备选方案：自定义轻量模型或云端唤醒词 |
| 浏览器麦克风自动播放策略 | TTS 可能被拦截 | 引导用户点击一次页面激活 AudioContext |
| 向量模型较大 | RAG 首次加载慢 | 使用更小的 multilingual-MiniLM 模型 |
| Home Assistant 配置复杂 | IoT 集成门槛高 | 保留模拟设备作为默认 fallback |
